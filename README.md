# SSENSE Womenswear — Information Architecture Redesign

> A complete IA research and redesign cycle for SSENSE's womenswear shopping experience: from user research through card sorting and tree testing to an annotated Figma prototype.

## The Problem

SSENSE's womenswear section suffered from serious findability issues: an overly deep navigation hierarchy, unclear category labels, a poorly defined filtering system, and visibility problems (e.g., no visible size filter, overlapping filter/menu panels during scroll, small hard-to-read fonts). Users faced high cognitive load just trying to find products.

## My Role

Planned and executed the full IA research cycle — from study design through analysis to annotated prototype recommendations.

## Research Methods

| Method | Details |
|---|---|
| **Online survey** | 9 participants; browsing behavior, navigation pain points, satisfaction |
| **Semi-structured interviews** | 3 participants; deep dive into navigation, filter, and search usage |
| **Task-based observation** | Timed tasks (e.g., find black size 38 boots); noted confusion points |
| **Open card sorting** | 5 users (ages 19–25) via KardSort; uncovered mental models for categories |
| **Tree testing** | Validated the redesigned IA against the original |

## Key Findings

- **66.7%** of survey respondents felt confused by the excessive number of categories
- Navigation scored only **2.89 out of 5** — a clear gap between visual polish and functional usability
- **44.4%** browsed by category while **33.3%** relied on filters (brand, color) — two distinct user behaviors: casual browsers vs. goal-directed shoppers
- **Terminology mismatch:** users naturally said "New Arrivals" but the site used "Latest Arrivals" — a small label difference with real navigation cost
- Card sorting revealed users grouped items into intuitive buckets ("Clothing", "Accessories", "Sort", "Color") that didn't match the site's structure

## Design Solution

Based on the research, I restructured the IA in Figma:

1. **Advanced Filter system** — collapsed by default for casual browsers (reducing cognitive load), expandable into an organized hub (designers, colors, sizes, price sorting) for goal-directed users
2. **"Latest Arrivals" → "New Arrivals"** — aligned labels with users' actual vocabulary
3. **Dedicated Designers Page** — alphabetical designer browsing instead of mixing designers with product categories at the same level
4. **Single filter section** — consolidated scattered filtering tools that previously caused structural confusion

## Validation

Tree testing confirmed the redesigned IA outperformed the original: goal-directed users completed tasks with **less time and fewer navigation mistakes**. Prototype evaluations were universally positive — users appreciated the simplicity and having all filters in one place.

## Reflection

This project taught me that IA is the mental blueprint of a product — not how things look, but how they're logically structured in the user's mind. The most valuable lesson: designing is an ongoing process of testing assumptions, not a one-time deliverable. Peer feedback at every stage (from "avoid crowding" to "add annotations") directly shaped the final design.
